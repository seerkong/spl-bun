## 现在可以做什么

在 Web IDE 导入 CSV/TSV、JSON、XLSX/XLS 后，以 `input` 为数据集运行 Kon；当前结果以 `result` 交给报表。下载当前列的 Excel 模板，在 Excel 中调整标题、样式、合并或批注，然后上传该模板，填写 JSON 参数并渲染。HTML 预览与下载的 XLSX 来自同一渲染结果；改动来源或参数使旧结果失效。

报表作者可用 `*=field`、`${expr}`、批注 `expandType/expandExpr`，以及 `*=^sales!region` / `*=>sales!product` 表达分组与横向展开。父格支持显式地址、A0 取消继承、嵌套和多行区域；交叉格按原记录索引取同源交集，保留重复记录，空交集不回退全量数据。数据与模板输入不被改写。

新增 report-contract / report-logic / report-xlsx-support 三个包。纯内核只接收公开契约与显式求值器；XLSX support 在原压缩包上写入布局，保留 styles/theme 等未改文件项，并复制宽高、样式索引与合并。没有引入 nop-entropy 的 ORM、认证、工作流或容器；没有复制其 Java 源码或工作簿。

CSV 改为正式解析器，支持引号、换行、转义和 BOM；保留 `001` 等标识值。JSON 与序表保留后续行才出现的字段。core 与 SPL 成员 group/join 共用类型化元组索引，修复分隔符、类型强制转换和隐式大小写折叠引起的错误。窗口 sum 与 avg 各自累计，原生 `spl_window` 提供分区、稳定排序、排名和累计指标；IDE 有可运行的 Window 示例。

执行放在请求独立 worker 中，默认 10 秒时限，可取消，超时后下一次请求仍可运行。文件大小、布局与输出有边界。浏览器的在途旧响应不会覆盖新来源。

## 验证与边界

- 最终工作区 `bun test`：339 pass、0 fail，较原基线 306 个测试增加 33 个；864 expects / 57 files。
- `bun run build`：13 包全部成功；IDE、server、Kon 的额外 typecheck 成功。
- `bun run test:e2e`：14 个 Chromium 用例通过，含真实上传 / 计算 / 模板 / 下载并独立重读 XLSX、窄屏布局、在途响应失效和既有示例回归。
- 真实 ego-browser 操作也走通上传订单、派生金额、编辑模板参数、预览与下载；重新打开下载文件确认文本 ID 和金额类型。模板样式与主题文件项有逐字节回归，分组与交叉有具体数值反例。
- 纯 logic 无文件 IO 或隐式 JS eval，分层与请求输入不变有检查；旧 codument 的 diff 与 untracked 清单哈希保持初始基线。

原生 Excel 公式只支持普通 A1 引用的展开映射，并要求 Excel 重算；HTML 会明确提示。没有实现完整 Excel / Nop 层次公式求值器。两轴集合需独立；交叠兄弟区域、按行变化的列集合、动态 sheet 和受展开影响的图表 / 图片 / validation 等形态有明确拒绝边界。HTML 的样式展示也不等同于 Excel 的全部主题与打印布局。

仍需续作：真正有资源边界的 cursor / streaming / spill、更多关联与 pivot/unpivot、其余 SPL 函数和连接器，以及复杂报表公式与布局。逐项来源与拆分边界见 [剩余缺口](../recommendations/backlog.md)。已外迁的 domain / ORM 归相应基础库，不在当前仓库恢复。
